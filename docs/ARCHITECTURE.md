# 架构说明 · Architecture

## 整体架构

```
┌─────────────────────────────────────────────────┐
│              浏览器 (单页面)                      │
├─────────────────────────────────────────────────┤
│                                                 │
│   ┌─────────────┐       ┌─────────────────┐    │
│   │  UI 渲染层  │ ←──→  │  回合状态管理    │    │
│   │  (app.js)   │       │  (localStorage)  │    │
│   └──────┬──────┘       └─────────────────┘    │
│          │                                       │
│          ▼                                       │
│   ┌─────────────────────────────┐              │
│   │  核心算法 (solver-core.js)    │ ← 混淆保护  │
│   │  - splitSyllable              │              │
│   │  - passes                     │              │
│   └──────────┬──────────────────┘              │
│              │                                   │
└──────────────┼──────────────────────────────────┘
               ▼
        ┌─────────────┐
        │  词库 (JSON) │
        │  29,760 词  │
        └─────────────┘
```

## 数据流

1. **加载**:`fetch('idioms_pinyin.json')` → `{ word: [{i,f,t}×4] }`
2. **添加回合**:用户输入成语 → 查表找 `{i,f,t}` → 存入 ROUNDS
3. **筛选**:对每个候选 answer,跑 `passes(answer, ROUNDS)` → 保留返回 true 的
4. **渲染**:把 ROUNDS 和 cands 渲染到 DOM
5. **持久化**:ROUNDS 写入 `localStorage`,关闭浏览器后还在

## 关键算法

详见 [ALGORITHM.md](ALGORITHM.md)。

## 性能

- 词库大小:29,760 个成语
- 预计算后,`passes()` 每次 O(N × M × P) = O(29760 × 10 × 12) ≈ 3.5M 操作
- 实际筛选一次约 10-50ms
- 实时筛选体验流畅

## 已知限制

- 候选 > 500 时只显示前 500(按字母/词频排序后可重排)
- localStorage 跨域名隔离,不能跨浏览器同步
- 词库基于 antfu/handle 2023-02 之前的数据,2023 年 2 月之后的新成语可能不覆盖
